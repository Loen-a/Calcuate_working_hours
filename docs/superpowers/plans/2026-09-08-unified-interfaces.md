# Unified interfaces and shared business features

**Goal:** Integrate the local-main visual interface into main, keep the original Python work-hour rules, and expose both interfaces with shared leave, backup, and holiday features.

**Approved scope:** New/old interface switch (new by default, browser remembers selection and viewed date); full-day leave excluded from targets, balances, forecasts and missing-entry reminders while preserving punches and manual calendar overrides; JSON export/import; automatic holiday calendars with explicit refresh, cache and offline fallback. No second backend or second live database.

**Architecture:** Existing Flask, WorkHoursStore and domain functions remain authoritative. React components from local-main consume a Flask JSON dashboard, never independently calculate attendance or forecasts. Both views use the same service/storage operations. Frontend build is served by Flask as packaged static assets. Frontend tooling is only needed for development/build.

## Data and integration contracts

- `build_forecast(..., leave_days=None)` accepts optional excluded dates; original callers remain valid.
- `WorkHoursStore.set_leave(work_date, enabled)`, `list_leave_days(start, end)`, `get_theme()`, `set_theme(theme)`, `get_holiday_cache(year)`, `set_holiday_cache(year, holidays, fetched_at)`.
- New tables: `leave_days(work_date TEXT PRIMARY KEY)` and `holiday_cache(year INTEGER PRIMARY KEY, payload_json TEXT NOT NULL, fetched_at TEXT NOT NULL)`; theme uses existing settings. Preserve original entries and calendar_overrides.
- Calendar precedence: manual override > automatic holiday/compensating workday > weekday fallback; independently exclude leave dates from computation.
- Flask dashboard returns raw minutes and display labels generated by Python, plus dates, entries, leave, effective calendar and settings. React only formats date/navigation/plot placement.
- Backups use version 3 with entries, settings (period/theme), nonWorkingIntervals, calendarOverrides, leaveDays and holidayCache. Legacy import preserves main-only categories not present in old files, rejects incompatible non-null counts flags and does not create fake midnight punches for leave-only legacy records.
- Mutating backup import always requires explicit product confirmation and is atomic; no live user database is used by tests or acceptance runs.
