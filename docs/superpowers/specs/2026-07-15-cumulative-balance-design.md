# 月内累计余额设计

## 目标

在“预测与记录”表格中用“累计余额”替换“建议下班”，让使用者看到每个已完成工作日相对 9 小时目标的当日差额，以及从自然月月初累计到该日的余额。

## 计算规则

- 每个自然月从 0 分钟开始，跨月不结转。
- 当日差额等于有效工时减去 540 分钟。
- 累计余额按月内工作日日期升序累加当日差额，可以为正数、0 或负数。
- 有效工时继续使用当前可配置非工作时间规则计算。
- 只统计同时具有上班和下班时间的工作日记录。
- 缺失记录、未下班记录和未来预测不改变余额，并在该行显示 `-`。
- 默认周一至周五参与计算；节假日排除，调休上班日参与。
- 周模式仍从当月第一个工作日开始计算，因此当前周余额包含月内前序周数据。
- 修改历史打卡、日历标记或非工作时间规则后，余额随页面预测自动重算。

## 界面

- 删除表格中的“建议下班”列，增加“累计余额”列，表格总列数保持不变。
- 有记录的余额单元格以累计余额为主，并在下一行显示“当日 ±差额”。
- 正数使用绿色，负数使用红色，0 使用中性色；格式沿用 `+10分钟`、`-40分钟`、`0分钟`。
- 没有完整记录的行显示 `-`。
- 建议下班的领域计算和字段暂时保留，仅从 Web 表格隐藏，避免扩大本次功能范围。

## 数据流

`build_forecast()` 已读取整月工作日、记录、日历覆盖和非工作时间设置。它先按整月日期顺序生成当日差额与累计余额，再把对应值放入当前周或当前月的 `DayForecast`，因此不需要新增数据库字段或迁移。

## 验证

- 领域测试覆盖正向、负向、零差额、缺失记录、周模式继承月内前序余额和跨月归零。
- Web 测试确认“建议下班”列被替换、累计值和当日差额正确输出、缺失记录显示 `-`。
- 完整测试、Poetry 校验和桌面/手机浏览器检查必须通过。
