# 2026-07-20 请假功能

## 做了什么
- **WorkEntry 加 `leave?: boolean`**（前后端同步）——请假天标记，全天请假不录打卡时间。
- **EntryModal**：工作日弹框出现「请假（全天）」ochre 复选框；勾选后 In/Out 时间选择器隐藏，`valid` 直接为 true，保存不再需要时间输入。
- **计算全链路跳过 leave 天**：`useMonthStats` / `Dashboard.remainingWorkdays` / `TrendChart` / `App.missedPast` 全部加 `e?.leave continue`——请假不贡献 `done`/`entered`/`workdayEntered`，不参与盈余缺口、走势图持平、漏打卡提醒跳过。
- **推荐下班目标日**：今天若是 leave 日自动跳下一个 workday（`todayEntry` truthy → 不选今天）。
- **日历格**：leave 天显示 ochre「假」徽标，不显工时。
- **后端 schema + db + repo + api**：`leave: bool = False` 加进 Pydantic model；SQLite `work_entries` 表加 `leave` 列（`ALTER TABLE` 迁移）；repo 层 `_row_to_entry`/`upsert_entry`/`replace_entries` 全支持读写。

## 决策
- **以天算请假**，不按小时分段——全天请假就勾，不录上下班时间。
- **`in`/`out` 不依赖空串**：请假时前端发 `{ in: i || '00:00', out: o || '00:00', leave: true }`——后端 Pydantic 要求 HH:MM 格式，`00:00` 作兜底；`validate_order` 加 `if self.leave: return self` 跳过后端校验。
- **请假天完全踢出盈余**：`balance = done − 9 × workdayEntered` 公式不动，但 `done`/`workdayEntered`/`entered` 全部跳过 leave。请假天不会制造 9h 缺口。

## 踩坑
- 后端 `WorkEntryPayload` 有 `extra="forbid"`，加 `leave` 字段前任何带 `leave` 的请求直接 422。→ `schemas.py` 加 `leave: bool = False`。
- SQLite ALTER TABLE 后 `sqlite_master` 里保存的是**原始 CREATE TABLE SQL**，不反映 ALTER TABLE 加的新列约束。`_validate_schema` 的 `REQUIRED_CONSTRAINTS` 检查会因找不到 `leave` 约束而报错。→ 约束从 `REQUIRED_CONSTRAINTS` 移除（`PRAGMA table_info` 的 `EXPECTED_COLUMNS` 就够了）。
