# 数据存储与备份

## 唯一持久化来源

工时记录、主题偏好和节假日缓存统一保存在 SQLite 文件 `backend/data/workhours.db`。浏览器通过本机 FastAPI 的 `/api/*` 接口读写数据，不使用 `localStorage` 作为正式数据源，也不会在后端不可用时创建浏览器副本。

数据库包含三张表：

| 表 | 内容 |
|---|---|
| `work_entries` | 以日期为主键的上下班时间与可选 `counts` |
| `preferences` | 单行主题偏好，取值为 `cool` 或 `teal` |
| `holiday_cache` | 按年份保存的 holiday-cn 映射与获取时间 |

每次请求使用短生命周期连接。应用启动时创建缺失表并检查 `PRAGMA user_version`；当前 schema 版本为 1。数据库只保存原始工时输入，不保存净工时、月度盈亏等前端可计算结果。

## API 规则

- `GET /api/entries`、`PUT /api/entries/{date}`、`DELETE /api/entries/{date}`：读取、覆盖和删除工时记录。
- `GET /api/preferences`、`PUT /api/preferences`：读取和保存主题。
- `GET /api/holidays/{year}`：优先读 SQLite 缓存；未命中时由后端依次请求 jsDelivr 和 GitHub Raw。全部失败时返回 `fallback` 空映射且不缓存失败结果。
- `GET /api/backup`：下载 version 2 完整备份。
- `POST /api/backup`：上传并恢复 version 1 或 version 2 备份。

API 写入成功后前端才更新界面状态。数据库错误返回安全的统一错误响应，不向浏览器暴露 SQL、数据库路径或堆栈。

## 备份版本与事务

version 1 是旧版结构 `{ version, exportedAt, entries }`。导入时只替换 `work_entries`，保留当前主题和节假日缓存，用于迁移旧浏览器数据导出的 JSON。

version 2 包含：

- `entries`：全部工时记录；
- `preferences.theme`：当前主题；
- `holidayCache`：按年份保存的节假日映射和 `fetchedAt`。

version 2 导入先完整解析和校验，再在单个显式事务中替换三类数据。任一字段不合法或任一写入失败时全部回滚，不留下部分导入状态。导出文件名精确到秒：`workhours-YYYY-MM-DD-HH-mm-ss.json`。

## 运行与文件管理

后端依赖由仓库内 `backend/.venv` 管理。首次安装使用：

```powershell
poetry -C backend install
```

启动、测试和其他 Python 命令统一使用 `poetry -C backend run ...`，禁止执行全局 `pip install`。生产式本地运行前先构建前端，再启动服务：

```powershell
npm --prefix frontend run build
poetry -C backend run uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

浏览器访问 `http://127.0.0.1:8000`，不要双击 `frontend/dist/index.html`。SQLite 文件由服务自动创建在 `backend/data/workhours.db`。

## 手动下载限制

网页仍不能静默把导出的备份写入指定目录。若希望下载默认落到项目的 `backend/data/`，需由用户在浏览器设置中修改下载位置；这项限制只影响手动备份文件的下载位置，不影响 SQLite 持久化。
