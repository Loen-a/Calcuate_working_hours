# doc/

项目的**详细文档**目录。根 `CLAUDE.md` 只放通用规则；具体业务逻辑、开发过程、踩过的坑按类别放在下面三个子目录。

## 子目录

- **`项目日志/`** — 按日期记的开发过程、关键决策、做了什么。先看 `项目日志/CLAUDE.md` 了解日志格式。
- **`业务规则/`** — 定下来的业务逻辑（工时计算、推荐下班、数据存储等）。业务代码变动前先看这里，确认没破坏规则。
- **`踩坑记录/`** — 实际遇到过的 bug：现象、root cause、修复、为什么不会再犯。**写"为什么会发生"比"怎么修"更重要**。

## 什么时候往 doc/ 写

| 写哪 | 写什么 |
|---|---|
| 根 `CLAUDE.md` | 通用规则 / 约定 / 命名表（一两行能说完的） |
| `doc/项目日志/` | 一段开发过程有多个决策 / 改动点（日期粒度） |
| `doc/业务规则/` | 业务逻辑定下来后（公式 / 阈值 / 状态机） |
| `doc/踩坑记录/` | 非 trivial 的 bug、值得记住的坑（runtime 错误、工具特性、浏览器行为） |

## 与其他文档的关系

- 根 `CLAUDE.md` → **规则**（给 AI 的行为守则，精简）
- `doc/` → **详细文档**（业务、日志、踩坑）
- `README.md` → **项目对外介绍**（功能、跑法、结构）
